# ADR-0001 · UI는 좌 탐색기 · 우 상세 2패널로, 값은 전부 표로 그린다

- **상태**: 채택 · 2026-09-06 (`51e15b7`)
- **범위**: config-provider (`src/ui.html`)

## 맥락

이 UI는 **본인이 복호화된 원본 평문을 직접 눈으로 확인하는 유일한 창구**다 (스펙 §4.4).
그런데 초기 구현은 아코디언 카드 목록이었다. 한 항목을 펼치면 다른 항목이 밀려나
"prod와 dev를 나란히 확인한다"는 §4.4의 요구를 화면 구조가 방해했다.

중간 단계로 **항목 × env 매트릭스 표**를 가운데 두는 안을 만들어 실제로 써봤다. 값을
나란히 보는 문제는 풀렸지만, 우측 인스펙터가 같은 값을 한 번 더 그리게 되어 같은 정보가
화면에 두 번 존재했다.

## 결정

Postman 워크스페이스 배치를 따른다. 화면은 세 덩어리다.

| 영역 | 크기 | 책임 |
|---|---|---|
| 상단 | 92px | 숫자마다 뜻을 라벨로 붙인 카드 5장 + 전역 동작 |
| 좌측 | 464px | 검색 + 컬렉션 트리 (**목록 책임**) |
| 우측 | 나머지 | 고른 키의 상세 (**값 책임**) |

- **값 표현은 예외 없이 표로 고정한다.** 환경별 값·참조·메타·별칭·CLI가 전부 표다
- 상세의 표는 2열로 놓는다. 한 줄에 담기는 글자가 줄어 눈이 덜 움직인다
- 표의 값을 클릭하면 그 자리에서 편집된다 (Enter 저장 · Esc 취소). 편집 버튼을 따로 두지 않는다

## 근거

- 카드보다 표가 같은 높이에서 더 많은 값을 **같은 자리에** 정렬해 보여준다. 스캔하는 눈이
  x축을 고정할 수 있다
- 목록과 상세의 책임을 나누면 같은 정보를 두 번 그리지 않는다
- 이 화면에서 가장 자주 하는 일이 "보다가 고치는 것"이다. 편집 버튼을 찾는 단계가 그 사이에
  끼면 매번 한 번씩 더 멈추게 된다

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 아코디언 카드 목록 (초기 구현) | 펼치면 다른 항목이 밀려 prod/dev 비교가 안 된다 |
| 가운데 매트릭스 표 + 우측 인스펙터 | 같은 값을 두 번 그린다. 표 하나에 env가 늘수록 열이 좁아진다 |
| 모달 편집 | 값 하나 고치는 데 창을 열고 닫는다. 편집 빈도에 비해 비용이 크다 |

## 결과

- prod/dev/stg를 한 표에서 나란히 본다. 아직 정의되지 않은 env도 값을 넣으면 생긴다
- 좌측이 컬렉션 트리를 맡으면서 [ADR-0002](0002-collections-separate-file.md)가 가능해졌다
- 1250px 미만에서는 상세가 1열로 떨어진다. 좁은 화면에서는 표 폭이 우선이다
- 외부 폰트·아이콘 CDN을 쓰지 않는다. 평문을 그리는 페이지라 나가는 요청 경로를 만들지 않는다
  (아이콘은 인라인 SVG, ui.ts의 CSP도 같은 기준)

## 재검토 조건

- env가 5개를 넘어 상세의 값 표가 세로로 길어지면, env 선택 탭을 다시 검토한다
- 항목이 수백 개가 되어 좌측 트리 스크롤이 실용성을 잃으면, 가상 스크롤이나 검색 우선
  화면으로 바꾼다
