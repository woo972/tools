# ADR-0002 · 컬렉션은 항목이 아니라 별도 파일에 둔다

- **상태**: 채택 · 2026-09-06 (`51e15b7`)
- **범위**: config-provider (`src/collections.ts`, `<store>/collections.yaml`)

## 맥락

키가 늘면서 논리적으로 묶을 단위가 필요해졌다 (UI 좌측 패널의 폴더). 저장 위치로 세 가지
후보가 있었고, 셋 다 "동작은 한다". 갈린 지점은 **축소 모드**와 **파일 스키마**였다.

## 결정

`<store>/collections.yaml`에 **key 이름만** 담는다. 값도 메타데이터도 넣지 않는다.

```yaml
collections:
  - name: "주문 도메인"
    keys: [ORDER_DB_HOST, ORDER_DB_URL]
```

- 한 key는 최대 한 컬렉션에 속한다. 옮기면 원래 자리에서 빠진다
- **컬렉션을 지워도 key는 지워지지 않는다.** 미분류로 돌아갈 뿐이다
- 어떤 컬렉션에도 없는 key는 '미분류'다 — 저장하지 않고 조회 시점에 계산한다
- 컬렉션 편집은 소유자 전용이다. 에이전트에게는 열지 않는다
- 항목 파일과 **다른 락**을 쓴다 (`.collections.lock`)

## 근거

1. **축소 모드에서도 정리할 수 있어야 한다.** 컬렉션을 항목 필드로 두면 secret 항목을 옮기는
   데 sops 재암호화가 필요해지고, 그건 age 개인키를 요구한다. 값이 아니라 정리 정보인데
   키가 없다고 정리조차 못 하게 되는 건 과한 대가다.
2. **스키마 오염을 막는다.** `public.yaml`/`secret.yaml`은 알 수 없는 필드를 파싱 실패로
   처리하는 엄격한 계약이고 git으로 공유된다. 화면 정리 정보가 그 계약에 섞이면 두 관심사가
   같이 흔들린다.
3. 값이 없으므로 그대로 커밋해도 안전하다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 항목에 `collection` 필드 추가 | secret 이동에 age 키 필요 → 축소 모드에서 정리 불가. 스키마 오염 |
| 브라우저 localStorage | 머신 간 공유 불가. "데이터로 존재한다"는 요구와 맞지 않음 |
| 별도 SQLite | 저장소가 YAML+git이라는 전제를 깬다. 사람이 손으로 못 고친다 |

## 결과

- 정리 도구가 데이터를 지우지 않는다 — 삭제는 되돌릴 수 없는 실수를 클릭 한 번으로 만들 수 있다
- 파일을 손으로 고쳐 없는 key가 남아도 조회 시점에 떨어뜨린다 (유령 행 방지)
- 회귀 13건으로 세 불변식을 고정했다: 삭제 시 key 보존 / 한 key 한 컬렉션 / 항목 파일 불변
- 새 API 6개 (`GET·POST /collections`, `PUT·DELETE /collections/{name}`,
  `PUT·DELETE /collections/{name}/keys/{key}`)

## 재검토 조건

- 컬렉션을 에이전트에게도 읽히고 싶어지면(예: "결제 관련 키 전부") 읽기 경로의 정책을 정해야 한다
- 중첩 컬렉션이 필요해지면 `keys` 평면 구조로는 부족하다
