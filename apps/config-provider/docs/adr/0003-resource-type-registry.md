# ADR-0003 · 종류(resource_type)는 등록된 목록에서만 고른다

- **상태**: 채택 · 2026-09-06 (`51e15b7`)
- **범위**: config-provider (`src/model.ts`의 `RESOURCE_TYPES`)

## 맥락

`resource_type`은 자유 문자열이었다. 실제 저장소에 `api_key`, `api-key`, `kafka_topic`이
섞여 들어갔다. 같은 개념이 여러 철자로 갈라지는 순간 **종류로 묶어보는 일 자체가 불가능**해진다.

## 결정

`src/model.ts`에 12개 목록을 두고 그 안에서만 고른다.

`endpoint` · `database` · `password` · `api_key` · `oauth` · `certificate` ·
`topic` · `bucket` · `webhook` · `feature_flag` · `account` · `other`

경계를 이렇게 나눈다.

| 경로 | 목록 밖 값 |
|---|---|
| API 쓰기 (`PUT /alias/{key}`, `POST /items`) | **400으로 거부**. 허용 목록을 에러에 싣는다 |
| 파일 적재 (기동·reload) | **허용**. 기동을 막지 않는다 |
| UI | 드롭다운에 `등록 외 · 파일에 있던 값`으로 남긴다 |

## 근거

- 쓰기를 막으면 새로 생기는 갈래는 차단된다
- 적재까지 막으면 손으로 편집한 저장소가 통째로 안 뜬다. **저장소의 진실은 파일**이고,
  분류 하나 때문에 값을 못 보게 만드는 건 과한 대가다
- UI가 목록 밖 값을 지우지 않는 이유: 화면을 열었다는 이유로 저장소의 값이 조용히 바뀌면 안 된다

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 자유 입력 유지 | 철자 갈라짐. 실제로 이미 발생했다 |
| 적재 시에도 거부 | 손편집한 저장소가 기동 실패. 고칠 방법이 UI인데 UI가 안 뜬다 |
| 사용자가 목록을 편집 | 목록이 곧 스키마다. 편집 UI를 만들 만큼 자주 바뀌지 않는다 |

## 결과

- `/status`가 `resourceTypes`를 함께 내려 UI가 별도 호출 없이 드롭다운을 그린다
- 목록을 늘리려면 `RESOURCE_TYPES`에 한 줄 추가한다 (코드 변경이 필요한 건 의도된 마찰이다)
- 회귀 2건: 목록 밖 값 400 거부 / 파일의 등록 외 값은 기동 통과

## 재검토 조건

- 목록에 없는 종류를 반복해서 필요로 하면 목록을 늘린다. 세 번 이상 반복되면 사용자 편집
  가능한 목록으로 바꾸는 것을 검토한다
